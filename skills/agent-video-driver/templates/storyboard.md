# 分镜表与确认门

复制本文件到工作目录的 `storyboard.md` 填写, 填完先给用户看, 拿到同意再渲染.
背景与偏好写到 `prompts/brief.md`, 本文件只装"这一条片子的时间与画面决策".

## 一, 启动确认门 (必须先问)

- [ ] 已告知预估 token 消耗量级
- [ ] 已告知中间帧数量与磁盘占用
- [ ] 已告知渲染耗时量级
- [ ] 已告知全量渲染与最终合成会长时间吃满 CPU, 开发机上会明显卡顿
- [ ] 已告知本会话只做这一条视频
- [ ] 已确认配色: 用户给定主色与底色, 或从三到五个色相方向里选定一个 (风格库的调色板只作兜底参考)
- [ ] 已确认是否分批次编码, 分批就写明批数
- [ ] 已确认确认模式: 逐步确认 (每阶段停下给用户看) / 一次确认 (判据客观的题材) / 放手一条龙 (用户说"你定就行", 每个岔口选了什么要写进本表与汇报)
- [ ] 立项单已问完并落进 `prompts/requirements.md` (主题, 受众, 收货, 必现与必不现的词, 自备素材, 时长档位, 画幅, 帧率等; 每项都有 2 到 4 条具名路径与一条推荐)
- [ ] 覆盖度与结构单已落进 `prompts/coverage.md` (用户选定的覆盖方案与时长结论)
- [ ] 风格与配乐单已落进 `prompts/style-and-score.md` (三张候选与挑定的一张, 配色, 配乐取向, BPM)
- [ ] 用户已明确同意开始

确认模式的选择依据: 事实与审美需要用户发言权的题材 (知识解说, 品牌故事) 用逐步确认; 判据客观的题材 (数据动画, 片头片尾) 可以一次确认跑完; 用户明确说"你定就行"时用放手一条龙, 但岔口决策要留痕.
三种模式下, 开头预览这一个交付节点都不可省略, 见第六节.

## 一之二, 合成确认门 (每次跑重活前各走一次)

启动确认门只覆盖一次, 全量渲染与最终合成各自还要再确认一次, 记录在下面:

| 门 | 探测命令 | 探测结论 | 采用的限额 | 用户是否同意 |
|:---:|:---|:---|:---|:---:|
| 全量渲染前 | `python scripts/resources.py --for render --frames <帧数>` | | 并行进程数 | |
| 最终合成前 | `python scripts/resources.py --for encode --frames <帧数> --out-dir <产物目录>` | | 线程数 / preset / 优先级 | |

填写判据:

- 探测结论要写清核数, 当前负载, 可用内存, 目标盘剩余空间, 以及是否建议拦截
- 判定为空间不足或负载过高时不要开工, 把影响与选项报给用户让他决策
- 未获同意时只跑 `assemble.ps1 -ProbeOnly`, 不做任何编码
- 强行开工要显式加 `-Force`, 并把理由写进本节

## 三, 段落表

| 序号 | 起止秒 | 起止小节 | 段落标题 | 演示内容 | 观众要读懂什么 | 元素入场拍 | 转场手法 | 声音 |

| 01 | 7.2 到 16.8 | 3 到 7 | | | | | | |
| 02 | | | | | | | | |
| 03 | | | | | | | | |
| 04 | | | | | | | | |
| 05 | | | | | | | | |
| 06 | | | | | | | | |
| 07 | | | | | | | | |
| 08 | | | | | | | | |
| 09 | 末尾 4.8s | 末 2 小节 | 片尾 | 结论, 来源, 制作信息 | 记住哪一句 | 1 / 3 / 5 | 压黑 | 配乐减法收尾, 留干净尾音 |

填写判据:

- 段落边界必须落在小节线上, 段落长度取 2 到 6 个小节的整数倍
- **观众要读懂什么 (reads)** 是这一段的定时清单: 一屏一次一件事, 读完的时间决定这一段的长度. 动作可以快, 含义要留够时间; 读不完就先减字数, 不要靠拉长停留硬撑
- **声音列**写这一段的三层声音状态 (环境层, 拟音层, 配乐状态) 与落在切点上的音色名; 约一半的切点什么都不放, 全片至少两处真实静默, 细节填进下一节
- 每段内部至少有一次数值或图形变化, 纯静态段落不超过 2 秒
- 任意两段的内部结构不得完全相同, 全片结构一样会让观感变平
- 元素入场一律写拍号, 不写秒数; 把 BEAT 改掉时所有元素应当整体跟着挪
- 关键句 (揭晓, 反转, 末屏) 要落在音乐能量发生变化的那一小节第一拍, 而那一小节是从 `audio_env.py --bpm --anchors` 的实测曲线里挑出来的, 不是先钉切点再补理由

## 三之二, 声音设计 (三层, 与段落同时定)

只有一条配乐的片听起来像 MV, 不像片子. 三层在写段落表时就一并定下来, 阶段 4 只负责按表做出来.

| 段 | 环境层 | 拟音层 (t / 音色 / 峰值) | 配乐状态 | 静默与声音转场 |
|:---:|:---|:---|:---|:---|
| 00 | 房间底噪 0.05, 全段 | 1.2 swell 0.26 | 引子, 只留 pad | 无 |
| 01 | 同上 | 7.4 click 0.16, 9.0 paper 0.30 | 推进, 加拨弦 | 该段末 1.5 秒真静默, 下一段的 thump 提前 4 帧进 (J-cut) |
| 02 | | | | |

填写判据:

- 拟音层逐条写成 cue 表 (t, 音色或素材路径, 峰值), 音色名与峰值表见 `references/audio-engine.md` 的拟音层一节; 峰值不填就用音色表缺省值
- 每个可见动作配一个声音, 材质对得上; 但不要每拍都切, 每屏 1 到 2 个
- 至少两处真实静默, 放在转折或情绪最高点之前; 至少两次用声音做转场 (下一场的声音提前进, 或上一场的声音拖过切点)
- 这段表填完跑一次 `python scripts/sfx.py audio/cues.json audio/sfx.wav --duration <时长>`, 让它自查密度, whoosh 次数与最长留白; 三个判据任一不达标就回去改表
- 用自产拟音时不必等素材; 有用户素材的 cue 把 `file` 写上, 同一 cue 两者都给时素材优先

## 六, 交付节点

| 节点 | 内容 | 交付路径 | 通过标准 |
|:---:|:---|:---|:---|
| 覆盖度与结构 | 带出处的知识节点清单加两到三个覆盖方案加重点配比 | `prompts/coverage.md` | 用户挑定一个方案, 时长结论明确 |
| 风格候选 | 三张同内容换风格的样图, 附档位, 完整度与绑题材的推荐 | 例 `temp/style_A.png` 到 `temp/style_C.png` | 用户挑定一张 |
| 配乐试听 | 两到三段 8 秒片段, 同一拍表换音色取向 | 例 `temp/score_A.wav` 到 `temp/score_C.wav` | 用户选定音色取向 |
| 挑定方向样图 | 两张: 标题卡与典型演示屏, 都附底色与强调色色值 | 例 `temp/style_title.png`, `temp/style_demo.png` | 用户看完给出回执, 认可配色与风格 |
| 分镜故事板 | 6 到 9 个关键镜头拼板, 每镜标镜头号, 景别, 时长与一句文案 | 例 `temp/storyboard_sheet.png` | 用户批准, 或放手一条龙时留痕即可 |
| 开头预览 | 渲染开头约 10 秒的带音轨连续成片, 停在拍点上不在半句切断 | 例 `temp/preview_intro.mp4` | 用户看完给出回执, 认可风格与节奏 |
| 完整成片 | 全片 | 例 `out/成片.mp4` | 第七节全部通过 |

交付纪律: 每一行都要先交出文件路径, 等用户回执, 之后才提问或进入下一决策.
静态样图只能判断配色与版面; 节奏, 转场与音画同步必须看带音轨的连续样片.
