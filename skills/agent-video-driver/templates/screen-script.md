# 屏文案表

复制本文件到工作目录的 `script.md`, 每一幕一个二级标题, 幕内一屏一行.
本表是 `scripts/timing.py` 的输入, 排程结果落成 `temp/plan.json` 与 `temp/plan.md`, 场景模块再从它取段落边界.

## 写法规则

- 一屏一句, 一屏只讲一件事
- 中文一屏不超过 20 字, 这是知识解说子模式的约束; 数据动画与产品宣传片这类同屏多元素的题材不受此限, 但仍要保证观众来得及看
- 每屏的最小时长是 3 拍, 估算公式见 `references/narrative.md`
- 第一屏就是问题本身或结论本身, 不做铺垫
- 屏号只作展示, 排程按表格出现顺序走
- 表格只取第二列为屏文字, 其余列随意, 一般留一列写这一屏要配的画面

## 排程

```
python scripts/timing.py script.md --bpm 100 --bars 45 --anchor 8:21 --json temp/plan.json --md temp/plan.md
```

- 每一幕的首屏会自动落在小节线上
- `--anchor 屏号:小节号` 用来把揭晓, 反转, 末屏钉在某一小节, 可以重复传; 屏号用跨幕连续编号, 小节号从 1 开始
- `--fix 屏号:拍数` 用来给公式屏这类来不及读的屏单独加长
- 排不下时会报清缺多少小节多少秒, 并给出解决路径, 此时应当精简文案或把总小节数调大, 不要硬压时长
- 余量会摊到全部合格屏上, 任一屏分到的额外时长不超过 `ceil(余量小节 / 合格屏数)` 个小节; **合格屏是最后一个锚点之后的屏**, 所以锚点越靠后, 能分摊余量的屏越少, 那几屏就会被拉得越长
- 文案量撑不起音乐长度时 (合格屏平均每屏多分到 2 小节以上) 会打印醒目告警, 给出内容所需小节, 音乐小节与三条解决路径; 此时优先按它的第 2 条把 `--bars` 改成接近内容所需, 而不是接受长停留
- `temp/plan.json` 里的 `bar` 字段是 0 基, 供场景模块与 `beats.py` 的输出对齐; 人要读的 `temp/plan.md` 表里的小节号是 1 基
- 摊薄只改变每屏停留时长, 不缩短总时长; 被拉长的屏内部仍要靠分镜自己安排运动, 以满足"纯静态段落不超过 2 秒"
