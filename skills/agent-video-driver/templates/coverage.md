# 覆盖度与结构单

复制本文件到工作目录的 `prompts/coverage.md`, 在阶段 2 末 (研究与核查做完, 文案编排之前) 交给用户.
本单决定"讲几个点"与每部分占多少, 它一旦定了, 分镜与配乐才有依据; 改它要按连带代价表报价.

交付顺序: 先把带出处的知识节点清单与两到三个覆盖方案做出来, 给出文件路径, 再请用户挑, 之后才写 `script.md`.

## 一, 知识节点清单 (带出处)

| # | 节点 | 一句话 | 来源链接 | 来源类型 | 删除或改写及理由 |
|:---:|:---|:---|:---|:---:|:---|
| 1 | | | | 原始 / 转述 / 估算 | |
| 2 | | | | | |

- 找不到可靠出处的直接删掉, 并在"删除或改写及理由"里写明
- 估算与转述要标注; 判定规则见 `references/content-and-rights.md`

## 二, 覆盖方案 (两到三个, 差别要看得出来)

| 方案 | 讲几个点 | 重点与配比 | 与时长档位的匹配 | 取舍 (舍弃了什么) | 是否推荐 |
|:---:|:---:|:---|:---|:---|:---:|
| A | | 例 主线 40% / 支撑 35% / 收束 25% | | | |
| B | | | | | |
| C | | | | | |

- 每一条方案都要写清舍弃了什么, 只写讲了哪些不算方案
- 推荐一条并写一句与题材绑定的理由, 不给方案打分
- 配比按占比写, 不按秒数写, 避免与排程口径打架

## 三, 时长与结构结论

| 项 | 结论 |
|:---:|:---|
| 采纳的方案 | |
| 总时长 (秒) | 例 108.000s, 与立项单档位一致或修正为 |
| 时长是否需要修正 | 例 内容量只需 84s, 建议把立项单的 108s 收到 84s, 或补一个支撑段 |
| 段落数与每段大致职责 | 例 8 段, 每段一个演示点 |
| 缺口处置 (若有) | 精简文案 / 缩短音乐 / 回头剪音乐后重复若干小节, 三选一 |

## 填写判据

- 内容量撑不起时长时不要静默把屏拉长: 按 SKILL.md 第一节报价, 并给三条路 (精简文案, 缩短音乐, 用 `scripts/loops.py` 找接缝后由 `scripts/cutmusic.py` 重复或剪掉若干小节)
- 方案里的重点配比要与立项单的"看完记住什么"对齐, 不对齐就说明方案选错了
- 用户挑定之后才写 `script.md` 与排程; 中途改覆盖度按连带代价表报价 (分镜, 拍表, 配乐, 全部帧)
- 本单不涉及配色, 风格与配乐, 那些在 `templates/style-and-score.md`
