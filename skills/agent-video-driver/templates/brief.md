# 简报 (brief)

复制本文件到工作目录的 `prompts/brief.md`, 开工时填一次, 之后每完成一个阶段就更新一次.
它是全片唯一的一份背景, 也是交给子代理的三样东西之一, 所以必须写全, 不能有"你懂的"这类省略.

## 为什么要单独维护一份

- 一条片子会跨很多轮对话, 背景散在对话里必然漂移, 后面某一步就会忘掉前面定过的事
- 子代理看不到主会话, 只拿得到这份简报加本阶段的提示词, 缺一项它就自己编一项
- 用户中途改主意时, 只要改这一份, 后续所有阶段的提示词都从它取最新的背景

## 填写规则

- 全部用中文, 术语保留原文
- 数值给到确定的量级, 不要写"大概""尽量"
- "不要什么"必须具体点名, 写清反例, 例如不要紫色霓虹, 不要每场都用同一个版式
- 拿不准的先留 `<待确认>`, 并在下一次汇报里问用户, 不要替用户决定
- 每完成一个阶段, 把该阶段定下来的结论追加进第七节, 不要改前面已经确认的内容

## 模板

```
<context>

一, 主题与内容
  主题: <一句话说清讲什么>
  题材形状: <时间线 / 因果链 / 由浅到深 / 对照 / 一问一答 / 单个故事>
  受众: <给谁看, 他们的知识水平>
  看完记住什么: <一句话, 全片所有取舍都以它为准>

二, 交付规格
  时长: <秒, 精确到毫秒>
  画幅: <1920x1080 / 1080x1920 / 1080x1080>
  帧率: <30 / 60>
  交付文件名: <主题_副题_时长.mp4>
  作者署名: <默认不加, 要加就写清文案与出现位置>

三, 音乐
  方案: <本技能合成 / 用户提供>
  若合成: <BPM, 小节数, 风格, 音色取向>
  若提供: <文件路径, 已用 beats.py 测出的 BPM 与首拍>

四, 视觉
  风格: <从 styles.md 里选一种, 或描述自定义风格>
  背景三色: <top / bot / light>
  调色板: <强调色 1 到 4 的十六进制>
  字体: <中文用什么, 数字用什么>
  画幅约束: <例如标题区高度, 安全边距>

五, 用户的偏好
  喜欢: <具体点名, 例如喜欢拼贴式构图, 喜欢密集运动, 喜欢真实照片>
  不要: <具体点名, 例如不要紫色霓虹, 不要每场同一个版式, 不要合成噪声当音效>

六, 输出与文件位置
  工作目录: <相对路径>
  帧序列: <temp/frames_xxx>
  配乐: <audio/score_xxx.wav>
  成片: <out/xxx.mp4>
  中间产物: <script.md, plan.json, storyboard.md 等>

七, 前面各阶段已经定下的事
  <每完成一个阶段追加一条, 写清结论与依据>

八, 待确认
  <拿不准的问题清单, 下一次汇报时问用户>

</context>
```
