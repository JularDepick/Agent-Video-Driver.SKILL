# 阶段提示词

复制本文件到工作目录的 `prompts/<阶段名>.md`, 每个阶段填一份, 填完先给用户看, 再照着做.
背景部分不在这里重复, 一律引用 `prompts/brief.md`.
机制说明见 `references/prompt-scaffolding.md`.

## 七个模块

| 模块 | 写什么 | 能不能省 |
|:---:|:---|:---:|
| `role` | 本阶段由什么角色来做, 以及这个角色最在意什么 | 每阶段必写 |
| `context` | 直接引用 `prompts/brief.md`, 只补本阶段新增的背景 | 每阶段必写 |
| `task` | 产出什么, 放到哪个路径, 用什么格式 | 每阶段必写 |
| `specs` | 规格: 尺寸, 时长, 帧率, 拍表, 数据来源, 验收阈值 | 按需 |
| `style` | 推荐的做法与理由, 明确标注是推荐不是规定 | 按需 |
| `avoid` | 明确不要什么, 要具体点名反例 | 按需 |
| `check` | 做完逐条看什么才算完成, 含硬底线 | 每阶段必写 |

## 填写纪律

- 每一行都要带理由, 只写结论的提示词会被机械执行, 写了理由模型才能泛化到没写的地方
- `avoid` 里不要写"别像 AI 做的"这类模糊指令, 要写成"不要紫色霓虹, 不要每场同一个版式"
- `check` 里的硬底线不能漏: 事实有出处, 素材许可与署名, 不画真人脸, 画面只依赖时间, 以及本技能验收标准里的各项判据
- 用户明确说过的事照用户说的写, 没说的按题材推断着填, 拿不准的写进 `brief.md` 的待确认

## 模板

```
<role>
  <这一步由什么角色做>
  <这个角色最在意什么, 一句话>
</role>

<context>
  <见 prompts/brief.md, 本阶段只补新增背景>
</context>

<task>
  <产出什么, 放到哪个路径, 什么格式>
  <要不要给用户看, 看哪一部分>
</task>

<specs>
  <尺寸, 时长, 帧率>
  <拍表来源: BPM, 小节数, 切点数组>
  <数据与来源: 哪些文件是事实依据>
  <验收阈值: 引用 references/verification.md 的判据>
</specs>

<style>
  <推荐做法 1, 理由>
  <推荐做法 2, 理由>
  <以上是推荐不是规定, 用户明确指定过的以用户为准>
</style>

<avoid>
  <不要什么, 具体点名>
</avoid>

<check>
  <逐条验收项>
  <硬底线: 事实有出处 / 素材许可 / 不画真人脸 / 同一帧每次都一样>
</check>
```

## 交接给子代理

大而自足的阶段交给子代理时, 只给它三样: `prompts/brief.md`, 本阶段的提示词文件, 以及需要读写的文件路径.
它看不到主会话, 所以这三样必须自足; 它交回产出后, 由主会话读产出并跑 `check` 里的验收项, 再给用户看.
