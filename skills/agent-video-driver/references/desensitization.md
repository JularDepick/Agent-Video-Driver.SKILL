# 去敏

去敏的对象不只是成片. 一条片子的敏感信息会出现在三层: 抽取产物, 成片上屏, 以及**做片过程里写下的每一份文档** (研究与核查记录, 删改汇报, 本参考文档的读书笔记). 第三层最容易被漏, 因为"记录删改"这个动作本身就在复制敏感信息, 而且引用即复制是无意识的习惯动作, 一次写对不等于后续不复发.

## 敏感信息藏在哪里

以自带署名的演示文稿为例 (其他来源同理, 按"作者与归属信息"这一类去找):

| 位置 | 典型内容 |
|:---|:---|
| 文档元数据 (docProps) | 创建者, 最后修改者, 公司字段 |
| 首屏与末屏的版权行 | 年份, 姓名, 机构, 邮箱 |
| 备注与讲者注释 | 提到的人名与内部称呼 |
| 文件名 | 作者名或机构名直接拼在文件名里 |
| 内嵌图片的 EXIF | 拍摄者, GPS, 相机序列号 |

- 抽取产物 (例如从演示文稿转出的内容记录) 落盘前先过一遍这张表.
- 过程文档里**引用**这些字段时只写形态与位置, 不回显原文.

## 三层去敏

| 层 | 对象 | 做法 |
|:---:|:---|:---|
| 一 | 抽取产物 | 从原始产物抽取内容时就地隐去个人信息, 隐去动作记录成"形态与位置" |
| 二 | 成片上屏 | 首屏与末屏不出现署名, 邮箱, 内部称呼; 版权行要么删要么改写成不含个人信息的一句 |
| 三 | 过程文档 | 删改汇报, 研究记录, 反馈与复盘材料全部按"形态与位置"写; 交付前对**每一个**交付文件跑反查 |

## 禁用词表与反查

- 禁用词表从**原始产物自动推导**, 不手工维护: 元数据的姓名字段, 版权行里的拉丁字母串, 文件名里的人名片段都是推导来源.
- 词表存放在**交付目录之外** (例如工作目录的 temp 下), 交付物里不能出现词表本身, 否则词表就成了泄露源.
- 反查脚本自身**不含任何敏感词**: 它读词表文件, 词表不在脚本里, 也不在脚本的注释里.
- 命中记录只写: 形态 (邮箱, 拉丁姓名, 电话号码), 长度, 位置 (文件加行号), 命中的词表条目编号; **不回显原文**.
- 反查时机: 每次往交付目录新增或修改文件之后, 以及交付前对全部交付文件跑最后一遍.

## 命中之后

1. 确认命中属于哪一层, 在那一层改掉 (改写或删除).
2. 若命中位于过程文档, 改完后**重跑反查**, 确认没有把原文复制到另一处.
3. 反查连续两遍零命中才算通过; 一遍零命中一遍命中是常态, 因为修改动作本身可能引入新的复制.

## 与既有规则的关系

- 删改汇报的格式 (不回显原文的要求) 见 content-and-rights.md 的删改汇报一节.
- 素材许可与署名是另一件事: 去敏处理的是"不能公开的个人信息", 许可处理的是"能公开但要署名的素材", 两者都过才算干净.
- 检查器是 `scripts/check_redaction.py`, 词表自动推导加交付目录反查, 退出码 2 表示命中.
