# 内容与合规

两条底线贯穿全片: 每一句上屏的话都能追到出处, 每一份外部素材都能说清许可. 前者决定可信度, 后者决定片子能不能公开发布.

## 事实来源判定

| 来源 | 判定 | 用法 |
|:---:|:---:|:---:|
| 论文与预印本 | 可靠 | 引原文数字与结论, 注明版本与年份 |
| 机构公告与官方通报 | 可靠 | 直接引用, 记录发布日期 |
| 档案与官方记录 | 可靠 | 作为一手依据, 记录档号 |
| 本人原话 (采访, 演讲, 自传) | 可靠 | 逐字引用, 标明场合与时间 |
| 权威媒体 (有编辑部与更正机制) | 有条件可靠 | 只用于事件时间线, 具体数字回到一手来源 |
| 百科类站点 | 不算 | 只当找线索的入口, 顺着它的引用找一手 |
| 自媒体转述, 短视频, 论坛帖 | 不算 | 不采用, 需要时按转述处理并写出转述者 |
| 模型自己的记忆 | 不算 | 必须联网核实后才可用 |

- 找不到可靠出处的说法直接删掉, 不要降级成模糊说法留在片子里.
- 估算要标注是估算, 写明估算方法与数值区间, 不要和实测数字排在同一行而不加区分.
- 二手说法要写清是谁的说法, 例如某机构在某个年份估算的某数值.
- 核实结果落成一张表: 事实点, 来源链接, 来源类型, 是否转述, 核实时间. 表位见 `templates/storyboard.md` 的事实核查节.
- 研究与事实核查阶段的角色是最在意出处的那一个, 角色写法见 prompt-scaffolding.md 的阶段与角色表.

## 删改汇报的格式

核实完成后向用户汇报, 固定四段, 每段都要给出具体条目而不是结论:

```
一, 选了哪几个知识节点
  <逐个列出节点标题与一句话结论, 每条后面挂来源>

二, 按什么规则删或改了哪些
  <逐项写原说法, 改后说法, 依据; 删除的也写出来>

三, 改正了哪些常见误传
  <逐项写常见说法, 实际说法, 依据>

四, 哪些地方没能看到原始出处
  <逐项写只能引用某机构的估算的位置, 机构名, 年份, 并标注为估算>
```

- 第二段与第三段要能对得上屏文案表, 用户看完就知道哪几屏的字会变.
- 第四段宁可长, 不要漏; 漏掉的估算在成片里会变成看起来确凿的数字.
- 汇报与屏文案表一并发给用户, 见 narrative.md 的事实与画面所指的一致性.

## 素材许可

判定顺序固定, 从高到低逐条落位:

| 优先级 | 许可状态 | 能否使用 | 条件 |
|:---:|:---:|:---:|:---:|
| 1 | 公有领域 | 可用 | 无需署名 |
| 2 | CC0 | 可用 | 无需署名 |
| 3 | CC BY | 可用 | 必须署名 |
| 4 | CC BY-SA | 可用 | 署名, 且改过的以同许可共享 |
| 5 | 保留所有权利 | 排除 | 不使用 |
| 6 | 来源不明 | 排除 | 不使用, 找不到文件页即视为来源不明 |
| 7 | 仅限非商业 | 排除 | 不使用 |
| 8 | 仅限教育 | 排除 | 不使用 |

- 许可必须人肉去文件页核实, 不能靠脚本假定. 脚本读到的字段可能过期, 也可能把并列多个许可的页面读成第一个.
- 同一文件在多个站点出现时, 以原发布页为准; 转载页的许可标注不作依据.
- 未采用的候选素材也要列出并写明原因, 例如许可为仅限非商业或找不到作者.
- 采用的素材汇总成一张表: 素材, 用途, 来源页链接, 作者, 许可, 是否修改过, 是否采用; 表位见 `templates/storyboard.md` 的素材与署名节.

## 署名产物

采用任何外部素材时, 交付一份 `credits.md`, 字段固定为六项:

| 字段 | 填写要求 |
|:---:|:---:|
| 标题 | 素材标题或文件页上的作品名 |
| 类型 | 图片 / 照片 / 插画 / 字体 / 音效 / 配乐 |
| 来源页链接 | 文件页地址, 不是图片直链 |
| 作者 | 署名主体; 匿名时写文件页给出的署名 |
| 许可 | 许可名称与版本, 例如 CC BY-SA 4.0 |
| 是否修改过 | 是或否; 是的话写明改了什么 |

- 改过的图要注明已修改, 裁剪, 调色, 拼接, 去背景都算修改.
- 改过的 CC BY-SA 素材, 其衍生件以同许可共享, 并在 `credits.md` 里写清这一点.
- 片内是否出现署名行由用户决定; 但 `credits.md` 无论片内是否署名都要写, 它是发布说明的依据.

## 字体与音乐

- 字体要确认商用许可, 包括随系统附带的中文字体与等宽字体; 把渲染结果用于公开发布属于再分发场景.
- 字体许可不明确的, 直接换成许可明确的开源字体, 不要先渲完整片再回头换.
- 本技能默认全代码生成画面与配乐: 画面由 Pillow 逐帧算出, 配乐由 NumPy 合成, 不引入任何外部图片与音频素材.
- 因此素材许可只在引入外部素材时才触发, 触发项为: 图, 字体, 音效, 现成配乐. 默认路线不触发, 不要把默认路线也说成有许可风险.
- 一旦引入外部素材, 上一节的判定顺序与本节字体规则同时生效, 并在 `credits.md` 与 `templates/storyboard.md` 的素材表里各记一条.

## AI 生成内容

- 不用 AI 生成真人的脸. 具名真人只能用自由许可的真实照片, 或只用姓名与文字.
- 使用 AI 生成的插画或画面, 要按平台要求勾选 AI 生成内容标注, 并在 `credits.md` 的类型栏写插画, 注明由 AI 生成.
- 画面里不出现 AI 生成的文字: 标题, 人名, 数字一律由代码排版, 生成式图片容易拼错字并伪造出不存在的标题.

## 发布前清单

| 项 | 判据 |
|:---:|:---:|
| 每行上屏文字都有出处 | 逐行能在核实表里找到对应来源 |
| 年份与数字与已核实文案一致 | 逐位比对, 无改写无四舍五入 |
| 素材许可已核实 | 每项都在文件页确认过, 无来源不明项 |
| credits 已写 | 六项字段齐全, 无空缺 |
| 改过的图已注明 | 每张修改过的素材都写了修改说明 |
| AI 标注已勾选 | 平台侧标注已完成, credits 内也已注明 |
| 响度与真峰值达标 | 集成响度 -16 到 -14 LUFS, 真峰值不高于 -1.0 dBFS, 方法见 verification.md 的响度与真峰值 |
| 时长精确到帧 | 与设计时长一致, ffprobe 核对 |
| 观感由用户过目 | 用户已完整看过并明确认可 |

## 一条纪律

- 无视觉能力的 Agent 不得凭想象交付, 要明确告知用户观感需要你过目.
- 客观指标能兜住画质, 响度与时长, 兜不住判断: 构图好不好看, 节奏拖不拖, 转场突不突兀.
- 交付时逐项写清哪些已经验过, 哪些要用户看; 用户没看过之前不要宣布完成.
- 字符图预览可以核对元素位置与文字成块, 但它不是观看, 不能替代用户过目, 方法见 verification.md 的字符图预览.
