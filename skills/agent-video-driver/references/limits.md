# 能力边界

这份文档回答一个问题: **用户提的这条片, 本技能做得到哪一部分, 做不到哪一部分.**

它存在的原因是: 本技能有一套很强的方法论 (量化判据, 两道确认门, 帧完整性硬闸,
无视觉能力下的验收手段), 但它的**画面与声音都是代码算出来的**, 这个决定同时封住了
能力面的两端. 如果不把边界写清楚, 风险是 Agent 撞上做不了的特征时照文档指引降级,
交付出"用户没要的东西", 而全程没有一处报错.

因此本文件的读者不只是开发者, 也是 Agent 在阶段 0 与门一时的查阅对象.
立项单第 17 项 (能力缺口声明) 就是拿本文件当对照表逐条核的, 见 `templates/requirements.md`.

## 一, 总览: 三栏

| 能力 | 能做 | 勉强 (能做但要改需求或改分工) | 做不了 |
|:---:|:---:|:---:|:---:|
| 画面 | 排版与动态字体, 几何图元, 图表, 卡片与版面家具, 3D 点云与隐藏线刻版, 印刷与 riso, 贴单张外部图片 (产品照, Logo, 界面截图, `canvas` 的 `image` 与 `image_panel`), 分层绘制 (`begin`/`end`), 曲线逐段生长 (`curve`) | 2D 运镜 (只有缩放与平移), 遮罩揭示类转场, 贴图框的越界与压字无自动检查 | 人物与角色表演, 实拍影像, 手绘笔触与水彩油画质感, 网页与 DOM 渲染, 真 3D 材质渲染, 粒子系统与流体模拟, 图元级自由变换与图层矩阵, 照片流与相册混剪 (有贴图但没有推移与转场编排) |
| 声音 | 程序化配乐 (管弦乐与键盘电子两族), 自产拟音 14 种, 音频包络回画面, 用户自备音乐的剪接与变速变调 | 第三类之外的其他曲风 (要新写音色), 静默段占比高的氛围曲 (判据要放宽), 无鼓的极简配乐 | 任意曲风 (摇滚, 爵士, Epic trailer, 芯片音, 佛音与世界音乐), 完整编曲重配, 多轨分层, 乐器分轨, 人声合成 |
| 数据 | 屏文案表排程, 图表数据在场景模块里写死 | 读 CSV 或 JSON 喂图表 (要自己写几行读文件的代码) | 实时数据联动, 外部数据库 |
| 语言 | 中英混排 (逐字字形回退), 拉丁字母重音字符 | 日韩 (字体表里没有 JP 与 KR 的候选, 要手工补), 多语言要自己建语言表 | 阿拉伯文与天城文 (字体表无候选), 竖排, 逐字真上标下标 |
| 交付 | 一条成片 (含封面, 缩略图), 分批与一次编完两条编码路线, 断点续跑 | 无音轨的成片 (编码脚本要加一路, 见第四节), 硬字幕 (要手工加字幕流) | 交互式或工程文件类交付, 可编辑工程格式 (AE, PR, Figma) |

## 二, 画面侧为什么是这个形状

画面引擎 `canvas.py` 的公开 API 只有五类原语: 线与几何图元 (line / poly / disc /
ring / rrect / arrow / arc), 整屏合成 (wash / cloud / composite / stamp /
multiply_img / bloom), 文字 (text / text_fit / text_cap / rich / measure),
裁切转场 (cut_sweep / cut_flash / fade_to_black / camera_settle), 以及外部图片
(image / image_panel).

于是:

- **擅长**的是"把信息排得好看并让它动起来": 数据可视化, 标题卡, 演示动画,
  界面感强的抽象图形. 这一类题材做到位时, 成片的可复现性与量化判据是别的工具给不了的
- **不擅长**的是"画一个像的东西": 任何需要表征性绘图的内容 (人, 物, 场景) 都不行,
  因为没有可用的绘图原语. `references/direction.md` 里"有角色的片要出模型表"那条,
  在本技能内部没有引擎支撑, 落"做不了"
- **折中的一类**是风格化图形: 手绘涂鸦那张牌靠的是线条抖动而不是笔刷, riso 与纸感
  那几张靠的是纸底与网点. 它们是"有意的风格化", 不是"手绘与印刷的完整能力"

3D 那一侧是点云 + 画家算法 + 隐藏线刻版 (`three.py`), 能做分子结构, 数据缎带, 机柜,
刻版这类**结构示意**, 不是真 3D 渲染. `styles.py` 里那张 soft-3d 牌自己写明了
"这套引擎是刻版点云不是真 3D 渲染, 质感靠三面光加接触阴影逼近, 不要承诺材质级细节".

## 三, 声音侧为什么是这个形状

两套引擎 (`orchestra.py` 管弦乐十种音色, `music.py` 键盘电子九种音色) 共用一张十档
逐小节意图表. 这个组合能做出层次与脉冲感明确的配乐, 做不出需要特定电声乐器的曲风.

判据也跟着收窄: `check_audio.py` 的 `--engine` 只有 orchestra 与 keyboard 两档
(拍点峰值比 1.3 与 1.8, 谱心区间各一档). 氛围曲的折叠包络天然低于 0.35 的主判据,
电子舞曲的高频占比常超过 35% 的上限. 所以**照现有判据去调一个新曲风, 会被判据劝退
回到管弦乐** —— 这是当前最需要用户知情的一个陷阱, 落"勉强".

相对地, **用户自备音乐是唯一能交付任意曲风的路径**: `beats.py` 反推拍表, `loops.py`
找接缝, `cutmusic.py` 按小节剪接, 再加上变速变调. 这条路线在音频侧的能力面比自产
宽得多, 优先向用户推荐.

## 四, 已知的缺位与它们的代价

| 缺位 | 现状 | 代价 |
|:---:|:---:|:---:|
| 无音轨的编码路线 | `assemble_core.py` 的混音步骤硬编码 `-map 1:a`, 没有"不要音轨"的开关 | 交付形态里的"无声循环展示"要手工绕, 落"勉强" |
| 硬字幕 | 两条编码路线都只做单音轨, 没有 `-c:s` 路线 | 要字幕的片要手工加, 落"勉强" |
| 数据文件入口 | 没有 CSV 或 JSON 的读取脚本 | 数据片要在场景模块里写死数据, 落"勉强" |
| 复杂度预算 | `references/performance.md` 有逐算子实测, 但没有汇总成"哪些想法便宜哪些昂贵"的账 | 用户提一个高复杂度需求时无法提前告知工期, 落"勉强" |
| 自定义字体 | `fonts.py` 认环境变量与系统目录, 不认工程内的 `fonts/` 目录 | 用户自带字体要手工改 `theme.py`, 落"勉强" |
| 贴图框的越界与压字 | `check_layout.py` 只抽文字绘制调用, **不抽容器**, 所以 `c.image` / `c.image_panel` 贴进来的框它看不见 | 贴图框压住文字或超出安全边距时没有任何自动检查, 落"勉强": 贴图框要自己核, 或统一用 `--safe-margin` |
| 贴图里的文字 | `check_redaction.py` 的反查只扫文本类扩展名 (md/txt/html/json/py/csv 等), **不解析图片像素** | 贴进来的截图或照片上如果有不该出现的文字 (账号, 邮箱, 内部地址), 去敏反查查不到, 要人工核, 落"勉强" |
| 贴图素材的许可与署名 | `credits.md` 能登记素材, 但贴图这一动作本身不留痕 | 交付时无法从产物反查"用了哪张图", 要靠 `credits.md` 与分镜表, 落"勉强" |

三条"勉强"里, 后两条是**新能力带来的新盲区**: 贴图解决了"做不了"的问题,
但也把一类原先不存在的东西 (像素里的文字, 位图的许可) 带进了流程, 而现有检查
覆盖不到. 用贴图能力时, 这两条要人工补上.

## 五, 边界怎么随技能演进更新

这份文档不是一次写完的. 每当有新的音色, 新的绘图原语, 或新的脚本入口落地,
**同一轮改动里要更新对应的那一栏**, 否则边界页会开始说谎, 而说谎的边界页比没有更糟.

判一条特征属于哪一栏时, 用这个顺序:

1. 引擎里有没有对应原语 (查 `canvas.py` 的公开方法, `dsp.py` 的基元)?
2. 有原语, 但**要用户自己写一大段**才能用上? 落"勉强", 并在第四节写清缺的是什么
3. 没有原语, 且写不出来? 落"做不了", 并给分流表里的出路
