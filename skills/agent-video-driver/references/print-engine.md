# 印刷与 riso 路线

原语在 `scripts/printkit.py`, 共用的 numpy 基元在 `scripts/imgnp.py`.

## 核心观念

**颜色不是给像素指定颜色, 而是把几块油墨版叠印算出来的**. 粉压蓝是真紫, 黄压蓝是真绿. 用乘法而不是赋值, 这是"像一张印刷品"与"像贴了色块"的分界.

## 口径与画布设置

所有原语都在**画布像素网格**上算, 也就是 `(H * SS, W * SS)`.

**印刷段落建议把 `SS` 设为 1**. 理由是网点自带抗锯齿(`soft` 参数), 不需要超采样; 而逐帧成本对像素数极敏感:

| 流程 | SS=2 (3840x2160) | SS=1 (1920x1080) |
|:---:|:---:|:---:|
| 四块版整帧 | 约 3100 ms | 约 280 ms |

差约 18 倍, 因为瓶颈是内存带宽而不是算术. 代价是矢量线条与小字失去超采样, 会略显硬边; 对印刷风格这通常可以接受, 甚至是想要的, 但**要按题材决定**: 片子以大字与色块为主就用 SS=1, 需要细线条与小字就保留 SS=2 并接受成本.

`cv.configure(SS=1)` 之后必须重新 `cv.ensure_bg(force=True, ...)`, 因为背景是在构建时按当时的 `SS` 烘进图片的.

## 纸底

```python
import printkit as pk
paper = pk.paper_field(cv.W * cv.SS, cv.H * cv.SS, base=(243, 238, 229), seed=11)
c.composite(paper, mode="over")
```

三层缺一不可:

| 层 | 参数 | 作用 |
|:---:|:---:|:---|
| 低频斑块 | `mottle=0.016` | 纸浆不匀 |
| 每像素细粒 | `tooth=0.020` | 纸面粗糙 |
| 各向异性纤维 | `fibre=0.012` | 纤维被拉长的方向性 |

少了纤维这一层, 纸底只是"加了噪点的纯色", 像屏幕不像纸. 实测纤维层让纵向与横向的梯度比达到 1.99.

一个实现细节值得知道: 纤维必须是**两路不同方向的噪声叠加**, 而不是把同一份噪声的两个方向都加进来. 后者相加之后又变回各向同性, 实测梯度比只有 1.01, 等于白做.

## 网点

```python
cell = pk.cell_for_width(cv.W * cv.SS)          # 按画布宽度换算
dist = pk.cached_dot_field(W, H, cell, 15.0)    # 距离场, 一次性
scr = pk.halftone(mem, cell=cell, angle=15.0, dist=dist)
```

**面积线性**: 半径取 `cell * sqrt(field / pi)`. 网点的面积是圆周率乘半径平方, 而每个网点分到的格子面积是 `cell` 平方, 两者相等才让"覆盖率等于 field"成立. 少除这个圆周率会让 `field=0.25` 量出 0.39 的覆盖率, 中间调整体偏重. 实测:

| field | 覆盖率 |
|:---:|:---:|
| 0.10 | 0.101 |
| 0.25 | 0.251 |
| 0.50 | 0.501 |
| 0.75 | 0.749 |
| 1.00 | 0.908 |

`field=1.0` 时量到 0.908 而不是 1.0, 是网点相接后的正常饱和: 实地就是靠点连成片.

**`cell` 要跟着画布宽度放大**. 1280px 宽时 `cell` 约 6 对应 133 lpi; 1920px 宽要保持同样的网线就要约 9, 3840px 宽要约 18. 用 `cell_for_width()` 换算, 不要照抄别的宽度的值.

**`soft` 是抗锯齿宽度(像素)**: 0.4 太硬(点发方), 0.6 太糊(丢网点感), 0.48 到 0.52 最像.

## 角度与网线: 两条实测结论

外部资料常说"网线角度必须错开, 相同角度会叠成规则花纹". 在数字管线里实测的结果与这句话不同, 值得按实测来做:

| 组合(两块 0.5 覆盖率的版相乘) | 低频标准差 |
|:---:|:---:|
| 同角度同网线 (9.0 与 9.0) | 0.0004 |
| 同角度异网线 (9.0 与 9.3) | 0.0737 |
| 错开角度 (15 度与 45 度) | 0.0015 |

- **同角度同网线自己不会打架**, 低频起伏可以忽略; 所以"同角度必出摩尔纹"这条在数字实现里不成立
- **真正的摩尔纹来自同角度但网线不同**, 低频起伏高出两个数量级. 而网线不同很容易被误用: 交付尺寸换算不一致, 或者给两块版取了不同的 `cell`. **所有版必须用同一个 `cell`**, 这是最要紧的一条
- **角度错开的真正好处是叠印能出中间调**: 落在中间值的像素比例从 6.1% 升到 7.9%. 同角度同网线时两块版的点完全重合, 重叠区要么都盖要么都不盖, 套印能产生的第四色就没有了

## 叠印与套印偏移

```python
for centre, width, angle, ink_name in pk.TONES:
    mem = np.clip(1.0 - np.abs(lum - centre) / width, 0.0, 1.0)
    scr = pk.halftone(mem, cell=cell, angle=angle, dist=dists[angle])
    c.multiply_img(pk.screen_img(scr, pk.INK[ink_name], white, inks[ink_name]))
```

- 默认分色表 `pk.TONES` 把明暗轴切成四段, 每段取一段三角隶属度, 相邻版刻意重叠一点, 重叠处叠印生成中间调
- 油墨不满实地: `plate()` 的 `alpha` 缺省 0.95, 于是压上去的颜色比油墨本色略浅, 这更接近真实印刷
- 油墨覆盖率 `ink_coverage()` 是低频起伏的乘数, 消除平涂的数码味; 乘进每块版的 `mem` 即可
- 套印偏移 `shift2(scr, (dx, dy))` 是 riso 的灵魂: 每块版平移几像素, 颜色边缘错开, 混出第四色. 编排上平时给 0, 某几拍拉到几个像素再"啪"地归位, 归位瞬间再叠一个反向抖动并指数衰减

## 明暗窗口

```python
d = pk.density(cov, lum, floor=0.10, gamma=1.0, lo=0.10, hi=0.80)
```

同一张明暗图只改窗口就能从"平的工作样片"变成"收紧的终片". `floor` 表达潜影(大片未曝光), `lo` 与 `hi` 是窗口上下端.

**浅底片上"最深的黑"靠的是窗口, 不是换墨色**. 不加窗口时终片最暗的 1% 可能只有 66, 全画幅 40 以下只有个位数像素, 也就是根本没有黑; 收紧窗口之后才有真正的暗部.

## 主版线

```python
line = pk.outline(cov, w=1)
```

覆盖率减去腐蚀后的覆盖率, 得到**内侧剪影线**. 一条细主版线能让形体从"照片"变成"版画". 实测线只出现在边缘: 内部为 0, 边缘为 1.

## 版面家具

用画布已有的原语拼即可, 不需要额外代码:

| 元素 | 要点 |
|:---:|:---|
| 裁切线 | 必须在**活件区之外**, 这才是真裁切线的位置 |
| 套准规 | 圆环加十字加两个彩色象限点, 最能一眼认出"这是印刷" |
| 折痕 | 中线两侧一压一提的极淡明暗, 幅度 0.006 量级 |
| 压印颗粒 | 比屏幕颗粒更细, 交给 FFmpeg 的 `noise` 滤镜, 不要画进帧里 |
| 图注引线 | 先斜线再肘弯, 端点一个小圆点 |

## 逐帧管线的正确组织

这是印刷路线能不能跑起来的关键. **把一次性产物与逐帧产物分清楚**:

| 步骤 | 一次性 | 逐帧 (SS=1) | 逐帧 (SS=2) |
|:---:|:---:|:---:|:---:|
| 距离场 (每个角度一张) | 0.4 到 0.6 秒 | 0 | 0 |
| 纸底 `paper_field` | 0.4 秒 | 0 | 0 |
| 油墨覆盖率 `ink_coverage` | 0.2 秒 | 0 | 0 |
| 网点 `halftone` 一块版 | 0 | 73 ms | 144 ms |
| 屏图 `screen_img` 一块版 | 0 | 55 ms | 277 ms |
| 乘法混合 `multiply_img` 一块版 | 0 | 67 ms | 236 ms |
| **整帧四块版** | 0 | **约 280 ms** | **约 3100 ms** |

四条纪律:

1. **距离场一定要预计算**: `cached_dot_field()` 会按 (宽, 高, cell, 角度) 缓存, 或者自己在项目开始时把每个角度的结果存下来. 不预计算等于每帧重算旋转点阵
2. **纸底与油墨覆盖率只生成一次**, 生成后存成 PNG 或直接在工程里复用缓冲, 不要每帧重算
3. **屏图用 `screen_img()` 而不是 `screen_u8()`**: 前者交给 PIL 的 `Image.composite` 在 C 里做, 比逐通道 numpy 生成 uint8 快约一倍
4. **不要同时留着很多全画幅缓冲**: 一张 SS=2 的三通道 float32 是 95MB, 留着几张会让后面同一段代码慢三倍以上. 实测同一个合成操作在干净进程里 95ms, 在累积了若干 SS=2 大缓冲的进程里 400ms. 用完就 `del` 并 `gc.collect()`

## 印刷场专属的坑

- **亮场上的暗字会被光晕冲灰**: 白底黑字时光晕会把亮底糊到字上. 该拍的画面要基本关掉光晕
- **"亮场"要做成乘法, 不是加色**: 用乘法压亮, 不要用加色; 加色会把同等亮度加到字上, 黑字直接变灰字
- **不要给印刷场加暗角, 扫描线, 色差**: 纸没有这些
- **不要让网点来自低分辨率重采样**: 网点是细节, 按交付尺寸算, 不要算一半再放大
