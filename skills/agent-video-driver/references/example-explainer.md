# 阶段汇报与回执范例 (科普讲解片)

一条**科普讲解片**走完九阶段时, 每一步的产物, 汇报与用户回执该写到什么粒度. 它不规定内容, 只规定详略.
每阶段的动作与判据见 `workflow.md` 与 `SKILL.md` 第一与第二节, 本文件只给汇报骨架与回执的连带后果.

## 怎么用这份范例

- 汇报骨架可以照抄句式, 把文件路径, 实测值与"要用户拍板的那一件事"换成自己这一条的
- `<占位>` 是必须自己量或自己定的值: 路径, 帧号, 屏号, 字面文案, 以及一切没在文末出处对照表里列过的实测数字. 不要填一个看起来合理的数
- 表格里的回执行全部是**示例文本, 非真实回执**, 照着真实回执的形态拟的; 引用时不要写成某次真实会话的记录
- 只有文末出处对照表列出的值才是项目里真实量测过的数, 引用时注明来源文件
- **结论放最后**: 先摆产物路径与实测值, 再说判据过没过, 最后才是要用户拍板的那一件事

范例工程的骨架值: 108.000s / 30fps / 1920x1080 / 100 BPM / 45 小节 (每小节 2.4s) / 3240 帧, 取自文末对照表; 主题与屏文字一律写成 `<主题>` 与 `<该屏文案>`.

## 阶段 0, 环境探测

**该交什么**: `prompts/requirements.md` (立项单, 与代价披露同一次问), `prompts/brief.md`, 一份探测报告与缺失项影响清单.

**该怎么汇报**:

```
环境探测跑完, 报告在 <探测日志路径>.
可用: FFmpeg 与 FFprobe 在 PATH 带 libx264 与 aac; Python 3.13 加 Pillow 12 与 NumPy 2;
中文字体键 <字体键> 命中 <字体文件路径>; 目标盘剩余 <占位> GB.
拦截项: 无 (或 <缺失项> 缺失, 影响 <影响>, 绕法只有 <绕法>)
沙箱限制: 命名管道不可用, 并行渲染只能按帧区间开独立进程.
渲染路线: 浏览器不可启动, 画面走默认的 Python + Pillow 路线, 不影响交付.
立项单已按你选的路径落到 prompts/requirements.md, 实际取到: 108s, 16:9 1920x1080, 30fps,
分批编码按体量给建议, 署名不加, 输出目录 out/, 文件名 <主题>-108s.mp4;
中间帧 3240 张, 1080p 下的磁盘占用按 <占位> 报 (门一的量级是 900 张约 200MB, 3240 张要自己估一次再报).

要你拍板的一件事: 时长档位是否就按 108s 走.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "环境没问题, 按 108s 走" | 无 | 进阶段 1, 提示词与 `brief.md` 一起给 |
| "先出 30s 的看看" | 时长档位改了: 拍表, 配乐, 排程, 全部帧, 全部卡点重做 (连带代价表, 改时长一行) | 改立项单第 6 项, 重新报价再开工, 不要先渲再问 |
| "全按推荐" | 无, 但要按纪律列出实际取到的值, 不许静默 | 上表即是列值的那次汇报 |
| "机器我等下要用, 别占满" | 无产物作废, 限额要提前收窄 | 记进 `storyboard.md` 的合成确认门一节, 两步重活都按调低后的线程数跑 |

**这一步最容易漏的**: (1) 把"开工同意"当成"合成同意", 两个重活各自还要再确认一次 (`pitfalls.md` 第 36 条); (2) 不先问代价就开渲染 (`pitfalls.md` 第 29 条); (3) 探测不过关不报缺失项与影响 (`workflow.md` 阶段 0).

## 阶段 1, 简报与提示词

**该交什么**: `prompts/brief.md`, 当阶段提示词 `prompts/<阶段名>.md` (照 `templates/stage-prompt.md` 的七模块, `role` 与 `task` 与 `check` 必写).

**该怎么汇报**:

```
prompts/brief.md 与 prompts/<阶段名>.md 填好了, 路径在上.
七模块里这次动了 <模块名> 与 <模块名>: <改了什么, 为什么>.
没写进 avoid 的禁区: <没有就说无>.

要你拍板的一件事: 提示词里 <该条> 是否就按这个写法定下来, 定了后面各阶段都按它走.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "提示词可以" | 无 | 进阶段 2, 产出与提示词一起交付 |
| "受众写错了, 是学生不是公众" | 本阶段提示词作废重填, `brief.md` 的受众一项同步改 | 按改后版本重做本阶段, 不在旧产出上打补丁 |
| "把 <某做法> 加进不要的" | 无产物作废, 但它进 `avoid` 后要一路留在 `brief` 里 | 写进 `avoid` 与 `brief`, 后续阶段不再试探 |

**这一步最容易漏的**: (1) 填好的提示词没和该阶段产出一起给用户 (`prompt-scaffolding.md` 交互纪律); (2) 用户改了提示词却只在旧产出上打补丁, 同上; (3) 用户拒绝过的做法没有进 `avoid` 与 `brief`.

## 阶段 2, 内容与文案

**该交什么**: 带出处的知识节点清单与删改汇报, `prompts/coverage.md`, `script.md`, 之后是 `temp/plan.json` 与 `temp/plan.md`.

**该怎么汇报**: 四段固定顺序, 见 `templates/storyboard.md` 第四节: 选了哪几个节点 / 按什么规则删或改了哪些 / 改正了哪些常见误传 / 哪些是转述或估算.

```
覆盖度与结构单在 prompts/coverage.md, 两方案的区别在"舍弃了什么"那一列.
按"找不到可靠出处就不写"删掉或改动的: <节点> 删掉, 理由 <理由>; <节点> 改写为 <新说法>.
改正的常见误传: <误传> 改成 <正确说法>, 依据 <来源>.
转述或估算: <条目> 是转述, 文中写明是谁的估算.
内容量核对: 文案需要 <占位> 小节, 音乐 <占位> 小节, 缺口 <占位> 小节.
不静默把屏拉长; 三条路是 精简文案 / 缩短音乐 / 回头剪音乐, 我建议 <哪一条>, 理由 <理由>.

要你拍板的一件事: 覆盖方案取 A 还是 B, 以及时长是否按内容量修正.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "讲 A 方案, 时长不改" | 无, `script.md` 按 A 的配比写 | 写 `script.md`, 排 `timing.py`, 进阶段 3 |
| "讲三个点改成讲五个点" | 覆盖方案重挑, 配比与段数重算, 分镜整体重排 | 先按连带代价表报价, 用户认了再改单重排 |
| "内容不够就收到 84s" | 时长变等于拍表变: 配乐, 排程, 全部帧, 全部卡点重做 | 改 `prompts/coverage.md` 的时长结论, 重排 `plan.json` |
| "某句出处不够硬, 删掉" | 屏长变化会让整片时间轴跟着挪 (改单屏文案一行) | 重排 `script.md`, 重跑 `timing.py`, 已排的锚点重核 |

**这一步最容易漏的**: (1) 内容量撑不起时长时静默把屏拉长, 不报缺口不给三条路 (`workflow.md` 阶段 2); (2) 覆盖度没定就写 `script.md` (`workflow.md` 阶段 2); (3) 事实没有逐条落到来源链接 (`SKILL.md` 第六节第一条).

## 阶段 3, 风格与分镜

**该交什么**: 三张**同内容**候选样图 (例 `temp/style_A.png` 到 `temp/style_C.png`, 附档位与完整度), 两到三段 8 秒试听 (例 `temp/score_A.wav`), `prompts/style-and-score.md`, 挑定后的 `STYLE.md`, `temp/plan.json` 与 `temp/plan.md`, `storyboard.md`, 分镜故事板 (例 `temp/storyboard_sheet.png`).

**该怎么汇报**: 交付顺序不能反, 先给**文件路径**再提问.

```
三张候选样图 (同一句正文, 只换风格): temp/style_A.png, temp/style_B.png, temp/style_C.png
配乐试听 (同一拍表, 只换音色): temp/score_A.wav, temp/score_B.wav
A <牌 id> <档位> 完整度 <详细牌 / 指导牌 / 总览牌>, 推荐理由绑题材: <一句>
B <牌 id> <档位> ...    C <牌 id> <档位> ...
排拍表: temp/plan.json 与 temp/plan.md, 100 BPM, 45 小节, 每小节 2.4s, 段落边界全部落在小节线上.
锚点先合配乐跑 audio_env.py 拿实测能量变化最大的小节, 再用 timing.py --anchor 钉上, 不是先钉切点再看曲线.
分镜故事板在 temp/storyboard_sheet.png, <镜头数> 个关键镜头, 最没把握的地方是 <占位>.
样图只能看配色与版面; 节奏, 转场与音画同步留到阶段 5 的带音轨连续样片判断.

要你拍板的一件事: 风格取 A / B / C, 配色方向取哪一个 (要落到明确色值).
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "取 C, 配色 <主色> 加 <底色>" | 无 | 落 `STYLE.md`, 色值写进分镜表, 进阶段 4 |
| "三张都不像, 换一批" | 三张候选与样图作废, 重出 | 重跑 `style_lottery.py --avoid <上一条的牌>`, 重出样图再问 |
| "风格取 C, 配色换成 <另一色相>" | 全部已渲帧作废 (场景结构可留), 样图与样片重出 | 出 `temp/style_title.png` 与 `temp/style_demo.png` 让用户确认色值 |
| "配乐太热闹, 换 <音色取向>" | 配乐取向变了要重做配乐 | 重出试听, 选定后再合整条 |
| "第 <N> 镜改成 <改法>" | 该幕时间轴与切点可能挪, 锚点要重核 | 重排段落表与 `plan.json`, 不在已排好的表上局部挪 |

**这一步最容易漏的**: (1) 只给一张候选, 或用标题卡当样图 (`workflow.md` 阶段 3 第 2 条); (2) 三张样图不是同一内容, 底板明度与强调色差别看不出来 (`templates/style-and-score.md` 第一节); (3) 先钉切点再跑 `audio_env.py` 看曲线, 判据变成自证 (`pitfalls.md` 第 59 条); (4) 只给"我打算用管弦乐"这句结论不给试听路径 (`workflow.md` 阶段 3 第 3 条).

## 阶段 4, 配乐先行

**该交什么**: `audio/score.wav`, `temp/score_env.npz` 与逐小节表 `temp/qa/audio_bars.md`, 锚点核对记录, `audio/sfx.wav` 与它的稀疏度自查, `check_audio.py` 的完整报告.

**该怎么汇报**: 重活前后各报一次; 前报要做什么与限额从哪来, 后报实测值与判据是否达标.

```
配乐已合成: audio/score.wav; 拟音轨 audio/sfx.wav; 逐小节表 temp/qa/audio_bars.md.
实测: 刺耳区 2 到 6kHz 占比 <占位>, 谱心 <占位> Hz, 温暖区占比 <占位>;
每 10 秒 RMS 起伏 <占位> 倍, 折叠包络起伏 <占位>;
拟音三项: 平均间隔 <占位> 秒, 噪声 whoosh <占位> 次, 最长两段留白 <占位> 秒;
锚点: 逐小节曲线变化量前列的小节是 <占位>, 与关键句对上的有 <占位> 个.
判据: 拍点能量比与频段占比 <达标与否>, 拟音稀疏度三项 <达标与否>.

要你拍板的一件事: 拟音密度是否就这样, 还是要再稀一点.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "配乐可以, 开工渲画面" | 无 | 进阶段 5, 先出代表帧与开头预览 |
| "镲太抢, 拍点听不出来" | 配乐重新合成, 相位与波形全变; 画面切点不动, 帧不作废 | 先按 `pitfalls.md` 第 21 与 22 条查压缩时间常数与持续层 RMS, 改完重量拍点能量比 |
| "音效太吵" | 重出 `audio/sfx.wav` 并重跑三项自查; 已渲帧不作废 | 改分镜表声音设计一节的 cue 表, 重跑 `sfx.py`, 混完重跑响度验收 |
| "配乐再长两小节" | 拍表, 配乐, 排程, 全部帧, 全部卡点重做 (改时长或 BPM 一行) | 先报价, 认了再回头改 `plan.json` 与分镜 |

**这一步最容易漏的**: (1) 合成后没做三件事就往下走 (导出包络挑锚点, 做拟音轨, 跑客观检查) (`workflow.md` 阶段 4); (2) 拟音全用噪声 whoosh 或没有真静默 (`pitfalls.md` 第 57 条); (3) 包络与画面帧率不一致, 只重渲画面不重跑导出 (`pitfalls.md` 第 58 条).

## 阶段 5, 分段渲染

**该交什么**: 代表帧字符图核对记录 (20 到 30 帧), 开头约 10 秒**带音轨**连续预览 (例 `temp/preview_intro.mp4`), 帧序列目录 (例 `temp/frames_proj/`), 字形审计报告, 一份资源探测报告.

**该怎么汇报**:

```
开头预览在 temp/preview_intro.mp4, 带音轨, 停在拍点上不在半句切断.
代表帧已逐张做字符图核对, 每段至少 2 帧, 共 <占位> 帧; 记录在 <占位>.
字形审计: <字体键> 全部通过; "回退链也找不到字形"的项 <有 / 无>.
资源探测 (resources.py --for render --frames 3240): 逻辑核 <占位>, 当前负载 <占位>,
可用内存 <占位> GB, 目标盘剩余 <占位> GB, 建议并行进程数 <占位>, 是否建议拦截 <占位>.

要你拍板的一件事: 认可节奏与音画同步就按建议限额全量渲染; 有哪一屏要改现在说, 现在改是重渲若干帧, 编码后再改是重渲加重编加重测.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "开头可以, 按限额全量渲" | 无 | 按探测的进程数开独立进程, 一个帧区间一个作业 |
| "这一屏文案改一下" | 该屏重渲, 且 `script.md` 重新排程, 屏长变化牵动整片时间轴 | 先报价, 改文案后重排 `plan.json`, 重核锚点, 重渲受影响区间 |
| "配色再深一点" | 全部已渲帧作废 (场景结构可留), 样图与样片重出 | 改调色板常量, 先出一帧或一小段确认再决定是否全量重渲 |
| "不用问我了, 直接做完" | 无产物作废, 但岔口选择要留痕 | 换放手一条龙, 岔口决策写进分镜表与交付汇报, 开头预览不省略 |
| "我这儿机器在忙, 等会儿渲" | 无 | 保留帧序列与预览, 不动全量渲染; 开工前重量一次探测 |

**这一步最容易漏的**: (1) 用一张静态帧代替带音轨的连续样片就要用户拍节奏与音画同步 (`SKILL.md` 第一节的静态样图只管配色与版面); (2) 渲染**进行中**改场景源码, 成片里是旧画面 (`pitfalls.md` 第 55 条); (3) 亮场画面用缺省字符图核验, 该加 `--ink` (`pitfalls.md` 第 54 条); (4) 探测判定应拦截时硬开工不说明 (`pitfalls.md` 第 35 条).

## 阶段 6, 逐屏终检 (渲染完成后, 编码前)

**该交什么**: 逐屏终检表 (stdout 记录或 `--md` 落表), 总览拼图, 异常屏的反查与处置记录.

**该怎么汇报**: 本阶段是 Agent 自查, 不占用户时间; 只有需要用户决策的问题才按连带代价表报价后再问.

```
逐屏表跑完 (qa.py temp/frames_proj --plan temp/plan.json), 总览拼图在 <占位>.
异常屏 <屏号>: 平均亮度 <占位>, p95 <占位>, 与上一屏 MAE <占位>.
反查 (scene_module.py screen <屏号>): 第 <幕号> 幕第 <幕内序> 屏, 场景函数 s_<名>,
起止帧 <占位> 到 <占位>; 处置 <重渲了哪几帧 / 判定为正常>.
重跑第 1 步后逐屏表 <已干净 / 仍有 <占位> 屏异常>.
全局屏号与幕号不是线性对应, 每一屏都反查过, 没有凭幕号往回推.

要你拍板的一件事: <不需要就说"无, 我继续往下走">.
```

**用户可能怎么回** (示例文本, 非真实回执):

| 回执 | 触发什么连带作废 | 下一步动作 |
|:---:|:---|:---|
| "继续" | 无 | 把"逐屏终检已通过"写进分镜表验收记录, 进阶段 7 |
| "屏 <N> 我想换个说法" | 该屏重渲, 文案变化牵动时间轴 | 报价, 重排, 重渲受影响区间, 重跑逐屏表 |
| "先别删帧序列" | 无产物作废, 清理顺序要改 | 帧序列撑到全部验收通过之后再删, 并写进验收记录 |

**这一步最容易漏的**: (1) 改帧前凭幕号猜屏号 (`pitfalls.md` 第 56 条), 必须先跑 `scene_module.py screen N`; (2) 还没确认不需要重渲就把帧序列删掉 (`workflow.md` 阶段 8 的清理顺序); (3) 逐屏表的异常提示没有二次核实就动手 (`workflow.md` 阶段 6 第 1 步).

## 阶段 7, 编码封装

**该交什么**: 交付成片 (例 `out/<主题>-108s.mp4`), 流信息与响度实测值, 一份资源探测报告, 分批路线的状态 JSON (例 `temp/assemble_state.json`).

**该怎么汇报**: 编码是重活, 前报限额后报实测值; 退出码 3 的语义要翻译给用户.

```
编码前探测 (resources.py --for encode --frames 3240 --out-dir out): 建议线程数 <占位>,
preset <占位>, 优先级 BelowNormal, 是否建议拦截 <占位>.
```
